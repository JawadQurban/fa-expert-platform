## 2. What shipped

Detail: `CHANGELOG.md` 2026-08-30 entry; commits `5ee9d77` (docs rulings),
`a245ebd` (BE-01), and the closing docs commit.

**BE-01 — persistence foundation.** Migration 01 creates the nine tables of
`10_DATABASE_DESIGN` §3.1–3.2 with the document's own names. The techniques a
future session must stay consistent with:

- **Append-only is enforced three times** — the context's API shape (no
  `DbSet<AuditLogEntry>`; `AuditEntries` is no-tracking, `AppendAudit` is the
  only write), a `SaveChanges` guard that throws, and the grant script
  `scripts/sql/audit-log-append-only.sql` (INSERT+SELECT, DENY the rest).
  LocalDB cannot demonstrate the grants (the developer is the owner), so in
  development the DbContext guard is the working enforcement.
- **Closed unions are closed in the database itself** — CHECK constraints on
  `ROLE.code` and `ROLE_PERMISSION.data_scope`, tested with raw SQL, because
  the rule must bind clients that never load the C# enum.
- **Absences continue to be the encoding** — there is no user→permission table
  (`BR-0801`, P-137), no channel column anywhere near notifications, and no
  credential column on `APP_USER` (`BR-0808`).
- **Integration tests hit real SQL Server** (LocalDB, throwaway database per
  run, migrated then dropped). No in-memory provider — it enforces none of the
  constraints under test.

**The liveness/readiness split** — `/health` touches nothing; `/health/ready`
consults the database and reports "not configured" while
`ConnectionStrings__ExpertHub` is empty. A test pins each half.

**BE-02 — INT-01, the flow in the API** (`0d8d842`). The framework's
OpenIdConnect handler runs code+PKCE — the playbook's non-negotiables are
what it validates by default — and the browser holds an HttpOnly/Lax cookie,
never a token. Techniques to stay consistent with:

- **Everything mounts under `/api`** (`P-166`) — `apiBaseUrl` ends with
  `/api`; in-app `v1` moved under it; health stays at the root.
- **Fail closed is the whole design**: unmapped role values grant nothing
  (`Q37` unanswered ⇒ authenticated, entitled to nothing), `returnUrl` is

  minutes, userinfo-vs-ID-token, logout scope; each lands as an env edit.
- **The flow is proven against a fake IdP with a genuinely signed ID token**

  the handler's backchannel, so the handler's real validation runs.

  throws at the UI); `authMode` requires both `apiBaseUrl` and a configured
  client (`P-168`); the dev placeholder is untouched.

## 4. Corrections — claims I made that were wrong

**Seven — and three of them are earlier claims from this same session, corrected by later increments’ tests.**

1. **The `USER_ROLE` unique index did not do what its own comment claimed.**
   The configuration comment said SQL Server's NULL-equal semantics would catch
   an unscoped duplicate assignment — but EF's first generated migration added
   its default `filter: "[scope_ref] IS NOT NULL"`, which exempts exactly the
   rows five of the six roles produce (P-140). Caught by reading the generated
   migration rather than trusting the configuration; fixed with
   `HasFilter(null)`, regenerated, and pinned by the
   `The_same_role_assignment_cannot_be_granted_twice` test, which asserts on an
   **unscoped** duplicate on purpose. The lesson generalises: **read every
   generated migration — EF's defaults are decisions.**
2. **I repeated the documented heredoc trap.** The previous record's
   environment-traps table says bash heredocs fail on large/Arabic content;
   the first docs-patch script hit exactly that before switching to writing
   the script as a file. The trap table works only if it is read first.

3. **Setting `options.Configuration` in a test PostConfigure did nothing.**
   My fake-IdP tests set it expecting the handler to skip discovery — but the
   built-in post-configure had already built a discovery-based
   `ConfigurationManager` from `Authority`, and **the handler consults the
   manager, not the `Configuration` property**. Every handshake hit real DNS
   and 500'd. Fix: replace `options.ConfigurationManager` with a
   `StaticConfigurationManager<OpenIdConnectConfiguration>`.
4. **The test ID token lacked `iat` and the protocol validator refused it**
   (IDX21314) — the bare `JwtSecurityToken` constructor adds `exp`/`nbf` but
   not `iat`; it must be an explicit claim.
5. **BE-02 shipped a wrong challenge posture and I described it as correct.**
   With OIDC configured, the default challenge scheme was the OIDC handler —
   so an anonymous request to a *data* endpoint was answered with a 302 to
   the identity provider instead of 401. BE-03's fail-closed test caught it;
   the cookie scheme now answers every default challenge and only
   `/api/auth/login` challenges OIDC, explicitly (`P-170`).
6. **BE-01 followed the design document into a wrong role code.** `sysadmin`
   came from `10_DATABASE_DESIGN` §3.2; the frontend contract says
   `system_administrator`, and the source map ranks the service file first.
   Migration 02 rewrites the constraint and the document is corrected
   (`P-171`) — the checklist lesson: **diff the contract before writing the
   schema, not after.**
7. **The playbook's BE-03 definition of done cannot be executed literally.**
   “Run `Access.test.tsx` against the real API” — but that suite pins the
   mock through its own `setAccessServiceForTesting` seam. The full-stack
   backend tests are the equivalent statement; the playbook entry now says
   so instead of promising the impossible.

8. **I framed FAST's registered redirect URI as a misregistration — it is the
   portal's own callback.** P-176 called it “wrong twice over”; the owner's
   correction (`P-178`) shows the flow is portal-first and the registration
   is internally consistent — what is missing is *our* callback alongside
   it, not a fix to theirs. The written ask to FAST survives unchanged,
   which is why the error cost words, not work.
9. **Putting FAST's values in `appsettings.Development.json` broke the suite
   — and the suite was right.** `WebApplicationFactory` runs Development, so
   the 503-while-unregistered tests suddenly saw a configured client. Moved
   to `launchSettings.json` env vars: `dotnet run` gets the testing IdP,
   tests keep the honest default. The lesson: dev conveniences that leak
   into the test environment change what the tests assert.

Not corrections, but near misses worth naming — this segment added two: the
DS `Field` label's textContent *starts with* the required marker
(`"*التخصص"`), which broke exact-label queries twice before a debug dump
showed it; and the full-form jsdom walk re-learned P-143's lesson (typing
keystroke-by-keystroke across ~20 inputs → `fireEvent.change` + longer
timeouts). Also: the first test run failed once
(the audit tamper test reused the appending context; a fresh context is both
the fix and the more honest test), and CA1711/CA1861 initially failed the
build — resolved in `.editorconfig` with reasons, not suppressed inline.

### Environment traps (new this session — the 2026-08-27 table still applies)

| Trap | Cost | Avoid it by |
|---|---|---|
| **`dotnet ef` can't use the API as startup project** | The Design package is `PrivateAssets=all` in Infrastructure, so the tool refuses | `--startup-project src/ExpertHub.Infrastructure` — the `DesignTimeDbContextFactory` makes Infrastructure self-hosting |
| **Global `dotnet-ef` is 10.0.11 against an EF 9 runtime** | Works, with a skew warning outside MSBuild | Nothing needed today; retire the skew with BE-21 |
| **EF's generated migrations fail the analyzers** (CA1861) | Warnings-are-errors turns generated style into build failures | `.editorconfig` marks `**/Migrations/*.cs` as generated code — never hand-edit a migration to please an analyzer |
| **CA1711 rejects `Permission`/`…Collection` type names** | Legacy CAS naming rule vs. the BRD's own vocabulary | `.editorconfig` `allowed_suffixes` — with the reason written next to it |
| **EF puts an `IS NOT NULL` filter on unique indexes over nullable columns** | Silently exempts NULL rows from uniqueness | Read the generated migration; `HasFilter(null)` where NULL-equal semantics are the point |
| **`OpenIdConnectOptions.Configuration` set in a later PostConfigure is ignored** | Handshake tests hit real DNS and 500 | Replace `options.ConfigurationManager` with a `StaticConfigurationManager` (and put the fake token endpoint on `options.Backchannel`) |
| **The OIDC protocol validator requires `iat`** (IDX21314) | The bare `JwtSecurityToken` ctor omits it | Add `iat` as an explicit `Integer64` claim in test tokens |
| **The handshake's Secure cookies vanish over http in tests** | Correlation/nonce cookies never return; the flow dies silently | `WebApplicationFactoryClientOptions.BaseAddress = https://localhost` and `AllowAutoRedirect = false` |
| **`Guid.ToString()` inside an EF projection runs in SQL and yields UPPERCASE** | Wire ids differ by casing depending on where they were formatted | Materialize (`ToListAsync`) first, map ids in memory |
| **`DefaultChallengeScheme = OIDC` turns API 401s into 302s to the IdP** | Anonymous data requests “succeed” with a redirect; fetch callers see CORS noise, not 401 | Cookie scheme as default challenge; name the OIDC scheme only in the login endpoint's `Results.Challenge` |
| **DS `Field` labels prepend the required marker to textContent** | `getByLabelText('التخصص')` finds nothing; the real text is `*التخصص` | Anchor with `/^\*?التخصص$/`, or match unanchored substrings |
| **DS `DatePicker` control labels default to English** | Tests can't find «اليوم»; users get an English "Today" inside an Arabic form | Pass `todayLabel`/`placeholder`/month labels from the content module |
