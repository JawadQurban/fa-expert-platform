# Session records

One file per working session, newest first. **Not a changelog** — `CHANGELOG.md`
already records *what shipped*, and `DECISIONS.md` records *what was decided*.
These files hold the part neither of those keeps:

- **The narrative** — what was asked, in what order, and why the work went the
  way it did.
- **Owner rulings given in conversation** — decisions made verbally that shaped
  the code but exist nowhere else in writing.
- **Corrections** — claims made during the session that turned out to be wrong,
  and what replaced them. A future session that re-derives a wrong conclusion
  because nobody wrote down that it was wrong has wasted the correction.
- **How to resume** — the exact state, and the next thing to do.

## Writing one

Use the **`session-record` skill** (`.claude/skills/session-record/`) — it
carries the full structure, the rules, and the facts to gather first. `CLAUDE.md`
makes the record a required end-of-session step and makes reading the newest one
a required start-of-session step.

## Convention

`YYYY-MM-DD--YYYY-MM-DD-short-slug.md` (start date, end date, slug).

Each record opens with a **Resume here** block, so someone picking the work up
does not have to read the whole file to start.
