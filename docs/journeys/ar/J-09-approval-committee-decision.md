# Arabic version

## الرحلة J-09 — قرار لجنة الاعتماد

**الواجهة:** اللوحة الداخلية

---

### نطاق الرحلة

تبدأ من لحظة اختيار صاحب الطلب تحويل الطلب للجنة الاعتماد (بعد قرار J-07/F3). تغطي: تشكيل صاحب الطلب للجنة (الأعضاء، السير، الإلزامي/الاختياري، أو إعادة استخدام قالب محفوظ)، سير مراجعة اللجنة المتسلسل، تحصيل البيانات البنكية من المتقدم بالتوازي مع الاعتماد النهائي، وعودة النتيجة النهائية لصاحب الطلب. تنتهي بتوفر نتيجة الاعتماد/الرفض النهائية — وبيانات المتقدم البنكية المكتملة — لصاحب الطلب، لينتقل بها لمرحلة إعداد الاتفاقية (J-10).

---

### رحلة المستخدم

١. صاحب الطلب يشكّل لجنة الاعتماد: يحدد الأعضاء، يرتب سيرهم، ويصنّف كل عضو إلزامي أو اختياري — أو يختار قالب لجنة محفوظ مسبقًا (قابل للتعديل لهذا الطلب دون التأثير على القالب الأصلي)
٢. تصل تذكرة الطلب لكل عضو حسب سيره المحدَّد
٣. كل عضو يتخذ قراره: اعتماد، رفض، أو طلب تعديل
٤. رفض عضو إلزامي يوقف الطلب فورًا؛ رفض عضو اختياري يُسجَّل كملاحظة فقط ولا يوقف السير
٥. عند اكتمال موافقة كل الأعضاء الإلزاميين، تعود نتيجة الاعتماد النهائية لصاحب الطلب
٦. بالتوازي، يستلم المتقدم إشعار "اعتماد أولي" يطلب منه استكمال بياناته البنكية — تُفتح له حقول جديدة بملفه لم تكن ضمن نموذج الطلب الأصلي
٧. عند حفظ المتقدم لبياناته البنكية، يُشعَر صاحب الطلب بأن البيانات اكتملت ويمكنه المضي في إعداد الاتفاقية (J-10)

---

### الخصائص الرئيسية والوظائف

**F1. محفّز تشكيل اللجنة**
الوصف: فور اختيار صاحب الطلب تحويل الطلب للجنة الاعتماد (القرار نفسه مُغطى بـJ-07/F3)، يبدأ تشكيل لجنة الاعتماد.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | عند اكتمال متوسط نتيجة المقابلة (من J-07) أو حالة الاستثناء (من J-08)، وعند اختيار صاحب الطلب "تحويل للجنة الاعتماد"، يبدأ تشكيل اللجنة (F2) |

**F2. تشكيل لجنة الاعتماد**
الوصف: صاحب الطلب يشكّل لجنة الاعتماد بنفسه، محدِّدًا الأعضاء وسيرهم وإلزاميتهم، مع إمكانية الحفظ لإعادة الاستخدام.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | عند تفعيل "تحويل للجنة الاعتماد"، يشكّل صاحب الطلب اللجنة — يحدد الأعضاء ويرتب سير موافقتهم |
| AC-2 | ضمن التشكيل، يحدد صاحب الطلب لكل عضو حالته: **إلزامي** أو **اختياري** |
| AC-3 | يمكن لصاحب الطلب حفظ التشكيل (الأعضاء + السير + الإلزامية) كلجنة مسمّاة قابلة لإعادة الاستخدام بطلبات مستقبلية |
| AC-4 | عند وجود لجنة محفوظة، يمكن لصاحب الطلب اختيارها مباشرة بدل إعادة بناء السير من الصفر |
| AC-5 | عند إعادة استخدام لجنة محفوظة، يمكن تعديل أعضائها/سيرها لهذا الطلب تحديدًا دون التأثير على القالب المحفوظ نفسه |
| AC-6 | عند اكتمال التشكيل (جديد أو من قالب محفوظ)، يبدأ سير الاعتماد بأول عضو، مُفعِّلًا F3 |

**F3. تنبيه العضو ومراجعة السياق الكامل**
الوصف: كل عضو بسير الاعتماد يستلم تنبيهًا بدوره، مع نتيجة الفرز ونتيجة المقابلة النهائية المجمَّعة، حتى يتخذ قراره على أساس كامل.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | عند وصول دور العضو بالسير، يستلم تنبيهًا بطلب بانتظار اعتماده *(US-0208)* |
| AC-2 | يعرض التنبيه/الشاشة نتيجة الفرز الأولي، ونتيجة المقابلة النهائية المُجمَّعة — لا التقييمات الفردية منفردة — أو حالة الاستثناء وسببها إن وُجدت، مجتمعتين *(US-0208)* |

**F4. سير الموافقة**
الوصف: قرار موحّد على الطلب ككل، يسير وفق ترتيب الإلزامي/الاختياري المحدَّد بـF2، وينتقل تلقائيًا بين الأعضاء، ويتوقف فورًا فقط عند رفض عضو إلزامي.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | يصدر قرار لجنة الاعتماد على الطلب ككل، بناءً على النتيجة الموحّدة — لا قرارات منفصلة لكل خدمة *(BR-0209)* |
| AC-2 | عند موافقة عضو، ينتقل الطلب تلقائيًا للعضو التالي بالسير المحدَّد، دون تأخير يدوي *(US-0209)* |
| AC-3 | عند رفض عضو **إلزامي** بأي نقطة، يتوقف الطلب فورًا برفض نهائي *(BR-0210، مُحدَّدة للإلزاميين)* |
| AC-4 | لا يُعتبر الطلب "معتمدًا نهائيًا" إلا بموافقة جميع الأعضاء **الإلزاميين**؛ رفض أي عضو **اختياري** يُسجَّل كملاحظة ضمن سجل القرار فقط، دون أي تأثير على استمرار السير أو النتيجة النهائية *(BR-0211، مُعدَّلة)* |
| AC-5 | عند اكتمال الاعتماد النهائي، تعود النتيجة لصاحب الطلب (F5)، ويُفعَّل بالتوازي تحصيل البيانات البنكية (F6) |

**F5. عودة النتيجة لصاحب الطلب**
الوصف: بمجرد اكتمال سير اللجنة، تعود نتيجة الاعتماد النهائية لصاحب الطلب لينتقل بها للمرحلة التالية.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | عند اكتمال سير الاعتماد بنجاح، تعود نتيجة "معتمد نهائيًا" لصاحب الطلب |
| AC-2 | عند رفض عضو إلزامي، تعود نتيجة "مرفوض نهائيًا" لصاحب الطلب |
| AC-3 | عند "الاعتماد النهائي"، يبقى انتقال صاحب الطلب الكامل لإعداد الاتفاقية (J-10) مرتبطًا باكتمال البيانات البنكية للمتقدم (F6) |

**F6. تحصيل البيانات البنكية من المتقدم** *(جديدة)*
الوصف: بالتوازي مع الاعتماد النهائي، يُشعَر المتقدم باستكمال بياناته البنكية، وهي مطلوبة قبل المضي بإعداد الاتفاقية.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | عند اكتمال الاعتماد النهائي، وبالتوازي مع F5/AC-1، يستلم المتقدم إشعار "اعتماد أولي" يُعلمه باستكمال بياناته البنكية |
| AC-2 | عند استلام المتقدم للإشعار، تُفتح له حقول جديدة بملفه (قسم البيانات البنكية) لم تكن ضمن نموذج الطلب الأصلي |
| AC-3 | حقول البيانات البنكية المطلوبة: الدولة المتواجد فيها البنك، المدينة، اسم البنك، اسم الفرع، رقم الآيبان (IBAN)، رمز السويفت (SWIFT)، الاسم على البطاقة البنكية، رقم الحساب — جميعها إلزامية |
| AC-4 | عند حفظ المتقدم لبياناته البنكية، يُشعَر صاحب الطلب بأن البيانات اكتملت ويمكنه المضي بإعداد الاتفاقية |

**F7. طلب تعديل**
الوصف: أي عضو بالسير يمكنه طلب تعديل بدل قبول أو رفض، مع ملاحظة إلزامية مرئية لكل الأعضاء.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | يحق لأي عضو بسير الموافقة طلب تعديل بدل قبول أو رفض، بملاحظة إلزامية *(BR-0217)* |
| AC-2 | تظهر ملاحظة التعديل لكل أعضاء اللجنة كتنبيه مرئي، لا لصاحب الطلب فقط *(BR-0217)* |
| AC-3 | يستلم صاحب الطلب ملاحظة التعديل المطلوبة، ويعيد عرض الطلب بعد تصحيحه *(US-0218)* |
| AC-4 | عند إعادة العرض، يستأنف سير الموافقة من نفس العضو الطالب للتعديل، دون التأثير على موافقات من سبقه بالسلسلة *(BR-0218)* |

**F8. الرفض النهائي**
الوصف: رفض عضو إلزامي يوقف الطلب فورًا برفض نهائي كامل للمدرب مباشرة.

| رمز AC | معيار القبول |
| --- | --- |
| AC-1 | عند اختيار الرفض (من عضو إلزامي)، تظهر رسالة تحذيرية توضح أن هذا الإجراء يرفض الطلب نهائيًا للمدرب مباشرة، وتُطلب موافقة صريحة قبل التأكيد |
| AC-2 | عند تأكيد الرفض، لا يكتمل دون اختيار سبب من قائمة أسباب الرفض الموحّدة *(BR-0219)* |
| AC-3 | عند اكتمال الرفض، يُشعَر المتقدم بالنتيجة والسبب |

### نقاط مفتوحة — بانتظار الحسم

١. **ديمومة البيانات البنكية**: هل هي جزء دائم من ملف المدرب (CAP-04)، تُستخدم لاتفاقيات/تجديدات مستقبلية، أو تُجمع من جديد كل مرة؟ يؤثر على J-14/J-15 لاحقًا — يحتاج تأكيد.

جاهزين لإعادة بناء J-10 على هذا الأساس.
