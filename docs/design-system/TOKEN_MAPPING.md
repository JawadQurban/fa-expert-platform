# Token Mapping

Curated, human-readable provenance for every **component-specific** design token
generated by `frontend/scripts/generate-tokens.mjs` (`--fads-sys-button-*`,
`--fads-sys-card-*`, `--fads-sys-header-*`, `--fads-sys-footer-*`, `--fads-sys-divider-*`,
and the shared `--fads-sys-typography-line-height-*` family).
This complements, rather than replaces, the machine-generated
`frontend/src/design-system/tokens/generated/token-map.json` — that file is the
source of truth (rebuilt on every `npm run tokens:generate`); this document is a
maintained-by-hand summary for reviewers who don't want to read raw JSON.

**Maintenance rule:** every time a new `--fads-sys-<component>-*` token is added to
`generate-tokens.mjs`, add a row here in the same commit. `docs/VISUAL_COMPLIANCE_WORKFLOW.md`
Step 5 references this file for that reason.

## How to read the "Source" column

Every token falls into one of two categories:

1. **Figma variable** — a literal entry in `references/figma/foundations/Light.tokens.json`
   (or `Values.tokens.json`), resolved automatically by `generate-tokens.mjs`. Shown as
   `Light.<Group>.<key>`. Re-verifiable any time by re-reading that JSON file.
2. **Live Figma MCP verified** — no named Figma *variable* exists for this value (e.g.
   a component's literal frame height, or a named *effect style* like a shadow), so it
   cannot be pulled from the local JSON export. It was instead captured via a specific
   `get_design_context`/`get_variable_defs`/`get_metadata` call against the live
   component during that component's visual-compliance pass, and hardcoded into the
   generator with a citation. Re-verifiable via the node ID cited in the corresponding
   `docs/FIGMA_<COMPONENT>_SPECIFICATION.md` §"Node Reference".

No token in either category is an invented/guessed value — every row below is one or
the other, never neither.

**Hover = Focused background, explained:** `--fads-sys-card-bg-hover` and
`--fads-sys-card-bg-focused` resolve to the same value because the live Figma
component genuinely binds both states to `Background/background-neutral-50` — this
was independently confirmed by inspecting both the Hover-state node (`30195:11409`)
and the Focused-state node (`30195:11589`) via `get_design_context`; Focused is
visually distinguished from Hover only by its added 2px border
(`--fads-sys-card-border-focus`), not a different background. Two separate tokens are
kept (rather than one shared token used for both) so a future Figma update that
un-couples them only requires changing one line, not a CSS selector.

**No Card token is a CSS alias of a Button token.** Several Card tokens happen to
share the same *value* as an existing Button token because both were independently
sourced from the same underlying Figma primitive (e.g. `--fads-sys-card-bg-disabled`
and `--fads-sys-button-disabled-bg` are both `#e5e7eb`, both independently sourced
from `Light.Global.background-disabled`) — this is expected (Figma reuses its own
global tokens across components) and intentional, not a shortcut: `Card.module.css`
never references `var(--fads-sys-button-*)`, and vice versa, per
`docs/VISUAL_COMPLIANCE_WORKFLOW.md`'s "fix only the component in scope" rule.
Confirmed by `Card.test.tsx`'s "does not repoint shared tokens" test.

**Vertical color values, explained:** the 4 Vertical-orientation nodes render as
pre-baked image assets in the extracted `get_design_context` markup rather than an
inspectable `background-color` — no color data could be read directly off them. The
4 colors above were applied to Vertical by extension from the shared `Color` variant
property (e.g. "Color=Primary, Line Type=Vertical" and "Color=Primary, Line
Type=Horizontal" are two states of the same declared `Primary` value on one component
set), not independently re-verified per orientation. Flagged **Needs Confirmation** in
`docs/FIGMA_DIVIDER_SPECIFICATION.md` §5 — non-blocking, since it follows directly
from the component's own variant structure rather than an unrelated guess.

**`inset`/`fullWidth` are not Figma tokens.** Both props reuse the existing, already-
generated, shared `--fads-sys-space-inset-md` token (no new Divider-specific spacing
token was added) — the official component has no `Inset`/`Full-width` variant at all
(spec §6); these are FADS-authored conveniences layered on top of the 8 official
Color × Line Type variants.

## Verification

Run `npm run tokens:check-coverage` (part of `npm run tokens:validate`) to confirm
every `var(--fads-*)` reference in any `.module.css` file resolves to a token defined
in `tokens/generated/tokens.css` or `tokens/tokens.css` — this catches dead references
but does **not** verify Figma provenance (a token can be "defined" yet still be a
placeholder value, as `tokens/tokens.css`'s own header comments document). This file
is the provenance record; `tokens:check-coverage` is the existence record. Both are
needed.
